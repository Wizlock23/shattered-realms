# Mobile Architecture v0.8.0

## Runtime

- **Capacitor 8** native shell
- Static HTML/CSS/JavaScript packaged under `www/`
- iOS native project generated by `npx cap add ios`
- No network dependency required for current game content

## Web assets

- `www/index.html` — app shell / campaign / collection / deck builder
- `www/css/app.css` — visual system plus iPhone safe-area/mobile rules
- `www/js/app.js` — current gameplay-app logic and content database
- `www/js/mobile-shell.js` — native detection, build info, save export/import, basic crash capture
- `www/battle/index.html` — v0.4.3 battle engine as a real packaged page rather than a base64 `srcdoc`
- `www/assets/` — reference/native art assets

## Save model

v0.8 intentionally preserves the `sr_v050_state` LocalStorage key so browser prototype saves can migrate into the packaged build during testing. Production should replace this with a versioned persistence layer and later an authenticated backend.

## Production migration targets

1. Card/catalog data → versioned JSON or backend content service.
2. Player inventory/currency → server-authoritative database.
3. Decks/campaign → cloud save + local cache.
4. Battle rules → deterministic shared engine with replay/event log.
5. Purchases → StoreKit 2 / Apple IAP entitlement validation on backend.
6. PvP → authenticated matchmaking + authoritative result validation.
